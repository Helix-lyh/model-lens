# 活跃编码题册（题库版本 20261008，10 题）

十道题各只跑一种语言：CP-09 到 CP-12 是 Python，CP-13 到 CP-15 是 Go，CP-16 到 CP-18 是 TypeScript。发给模型的只有每题的题面全文，外加运行器附上的 describe() 合同。题面不规定业务字段名。评分先读 describe()，再比较业务结果。每题 20 个独立观察点，满 20 才通过。

迁移价值：每题只替换实体名、资源名、租户名和具体数据，状态关系与判分断言仍成立；因此测的是跨业务的状态建模与约束推理，不是记忆某个领域词表。

公共运行限制：不得使用网络、文件、环境变量、随机数或子进程；每次调用独立。回答只含一个代码围栏。Python 入口为 `def solve(data) -> dict`，Go 入口为 `package solution` 的 `func Solve(input json.RawMessage) json.RawMessage`，TypeScript 入口为 `export function solve(data: any): any`。函数返回值是 `{trace, output}`，不要把这个 JSON 直接当作整段回答。

## CP-09 配额预占与恢复回放

**栏目 / 业务锚点 / 失败代价 / 主能力。** 编码；支付前的资源预占服务由订单编排器使用，输入来自订单事件和配额快照；错配会造成超卖或恢复后重复扣款；主能力为推理。

**为什么更难。** 同一事件流同时维护当前配额、订单状态和恢复点；恢复只回退业务状态，不回退已占用的幂等键，且恢复后的新事件仍要与旧历史区分。

**题面全文。** 你是支付前的配额服务。每种资源有一份数量。订单可以预占、提交、释放，也可以查看。预占把同一资源的多笔数量合并；资源不够，或订单已经存在，整单失败，数量不动。订单只能从已预占变成已提交。释放只作用于已预占或已提交，数量回到资源上，订单变为已释放。可以记下当前配额和订单的快照，再按快照编号恢复这两样；恢复不忘掉已经用过的事件编号，也不删掉已有快照。查看不改账。同一个事件编号再次出现不得改账，trace 这一项是 DUP。查看一个没有的订单时，trace 这一项是 MISSING。

**可机械判分的 20 点。** 预占成功；同资源合并；不足时原子失败；订单重复被拒；首次失败占用 id；重复事件为 DUP；合法 COMMIT；非法 COMMIT；RELEASE 返还；重复 RELEASE 不变；SNAP 内容不变；快照编号稳定；未知快照拒绝；RESTORE 恢复配额；RESTORE 恢复订单；恢复不清幂等表；恢复后新事件可执行；READ 已知订单；READ 未知订单；output 按字典序且 trace 等长。

**参考行为。** 参考实现使用 `quota`、`orders`、`used_ids`、`snapshots` 四个状态表；每个事件先做幂等检查，再在临时副本上验证，只有成功才提交副本。快照编号从 0 递增，恢复不产生新快照。

## CP-10 运输批次与截止窗口

**栏目 / 业务锚点 / 失败代价 / 主能力。** 编码；仓配系统在波次关闭前决定包裹进入哪个运输批次；错排会造成错过班次或把已关闭批次重新打开；主能力为推理。

**为什么更难。** 事件时间可能乱序，批次有容量、关闭时间和优先级；取消后再投递不能复用原批次位置，重放又必须保持原选择。

**题面全文。** 你是仓配的运输批次。每个批次有截止时刻和容量。包裹先登记，再接受进批次。接受时只考虑还没过截止、还没关闭、还装得下的批次，按截止时刻早的优先，其次优先级高的，再按批次编号。选定以后不能换批次。关闭只关指定批次，即使关闭时刻晚于截止也生效；关闭后不能再收新包裹。取消会归还已接受包裹占用的容量，并记为已取消，同一包裹不能再次接受。事件编号全局只占用一次，失败也占用，重复时 trace 是 DUP。

**可机械判分的 20 点。** OFFER 登记；重复 parcel；容量选择；cutoff 边界；优先级排序；batch id 平局；关闭批次排除；乱序 CLOSE；接受后拒绝换批；取消返还容量；取消后不可重接；未知 parcel；重复 id；失败占 id；READ 已知；READ 未知；接受状态；取消状态；批次 used 非负；输出排序。

**参考行为。** 维护 `offers`、`parcels`、`batches` 和 `used_ids`；ACCEPT 的候选批次每次从当前状态重新排序，已关闭或容量不足者跳过；CLOSE 不自动取消已有接受。

## CP-11 双区域灰度与回滚

**业务锚点 / 失败代价 / 主能力。** 发布控制器为值班工程师计算每个租户当前配置；错把灰度值扩散到全量会导致线上故障；主能力为推理。

**为什么更难。** 同一服务有基线、区域覆盖和租户灰度三层视图；回滚只影响指定发布版本，旧读请求仍按读时刻解析。

**题面全文。** 你是发布控制器。每个服务有基线配置，另有按区域和租户的覆盖。发布带版本、区域和租户范围；同一版本不能发两次。没有写区域表示所有区域，租户名单为空表示所有租户。查看时先找最近一次还没回滚的发布，再套用全区覆盖和租户覆盖；同一层以后写的覆盖先写的，删除掉的键就去掉。回滚让指定版本对之后的查看不可见，其他版本不动。可以拍下已发布和已回滚的集合，再按编号恢复；恢复不清除事件编号。事件编号重复时 trace 是 DUP。

**可机械判分的 20 点。** 全区基线；region 过滤；租户过滤；版本顺序；同层覆盖；delete；空 tenants；重复 version；回滚指定版本；回滚不影响其他版本；回滚后新发布；读时点隔离；未知服务；未知版本；重复 op；失败占 id；快照保存；快照恢复；read 排序；trace 与结果等长。

**参考行为。** 参考实现按事件顺序维护发布表和 revoked 集合；READ 只扫描当前可见版本，绝不把 SNAP 当作回滚。`set` 和 `delete` 在同一 override 中先 delete 后 set。

## CP-12 多租户身份合并

**业务锚点 / 失败代价 / 主能力。** 客服身份服务在用户合并后继续解析历史工单；错把不同租户或已撤销身份合并会泄露工单；主能力为推理。

**为什么更难。** 合并关系形成有向森林，查询要沿当前根解析；拆分只撤销一条边，不删除其他合并历史，且别名冲突要原子失败。

**题面全文。** 你是客服身份合并。用户按租户分开。同租户里可以创建、合并、拆开、查询。合并要求两边都存在、当前不是同一个根、也不会绕成环；成功后前者的根指向后者的根。拆开只撤销正好存在的那一条直接关系，前者重新成为自己的根，其他历史不跟着搬。查询给出当前的根；没有这个用户时，根用 states 里的缺失词。可以记下全部现有关系。事件编号重复时 trace 是 DUP，失败也占用编号。

**可机械判分的 20 点。** 创建；重复创建；跨租户拒绝；未知用户拒绝；根解析；合并成功；合并环拒绝；同根合并拒绝；分裂直接边；非直接边拒绝；分裂后根；历史边保留；lookup 缺失；snapshot；snapshot 编号；重复 op；失败占 id；租户排序；用户排序；trace 等长。

**参考行为。** 使用 parent 映射和 find-root；SPLIT 删除的只是一条当前直接边。快照是边的深拷贝，LOOKUP 不写状态。

## CP-13 账务冻结与部分解冻

**业务锚点 / 失败代价 / 主能力。** 风控在付款前冻结账户余额、在人工复核后部分解冻；错算可用余额会重复扣款或错误放款；主能力为推理。

**为什么更难。** 冻结按 hold id 独立，扣款消费冻结额而非可用额；部分解冻、取消和恢复需要同时维护余额、冻结明细和交易状态。

**题面全文。** 你是付款前的余额冻结。每个账户直接对应一个整数余额。冻结按冻结号独立，可用额是余额减去还没消费完的冻结。冻结要求账户存在、可用额够、冻结号还没有。扣款只消费该冻结号剩下的额度，扣完记为已扣。解冻只释放剩下的额度，放完记为已释放。作废只能作用于已经扣完的冻结，不把已扣金额退回余额。事件编号重复时 trace 是 DUP。

**可机械判分的 20 点。** 余额存在；可用额；HOLD 成功；余额不足原子失败；重复 hold；CAPTURE 全额；CAPTURE 部分；超额拒绝；RELEASE 部分；RELEASE 余量；VOID 状态；VOID 不返已消费；跨账户拒绝；未知 hold；重复 op；失败占 id；READ 载荷；holds 排序；余额不负；trace 等长。

**参考行为。** 所有金额用整数；HOLD/CAPTURE/RELEASE 在临时状态中校验，失败不得改变其他 hold。`available` 只扣未消费的冻结额。

## CP-14 批次库存与有效期

**业务锚点 / 失败代价 / 主能力。** 冷链仓库按批次和有效期出库；错用先进先出会发出过期货或浪费新鲜库存；主能力为推理。

**为什么更难。** 同一 SKU 的库存按 expiry、入库序号和订单锁定共同排序；过期清理、取消和部分出库交错，不能只维护一个总数。

**题面全文。** 你是按批次和有效期出库的冷链库存。处理每条事件前，先把有效期已到、且没有被锁住的数量清掉；锁住的数量不会自己回来。分配按有效期早、入库早、批次编号的顺序锁数量，不够就整单失败。同一订单不能分配两次。发货把锁住的数量变成已出。取消把还没发货的锁定量还回可售，订单不能再分配。事件编号重复时 trace 是 DUP。

**可机械判分的 20 点。** 到时清理；锁定不清理；expiry 边界；先进有效期；received 平局；batch 平局；原子不足；订单重复；SHIP；CANCEL 返还；已发不可返；取消后不可重配；未知订单；重复 op；失败占 id；READ 过期字段；批次排序；free/locked 守恒；多 SKU 隔离；trace 等长。

**参考行为。** 每个批次保留 free、locked、shipped 三个计数；过期只从 free 扣除。订单记录精确的批次分配明细，CANCEL 只返还 locked。

## CP-15 审批链与代理窗口

**业务锚点 / 失败代价 / 主能力。** 采购系统在金额达到阈值时选择审批人；错误跳过审批会造成越权采购；主能力为推理。

**为什么更难。** 审批链按金额和部门版本解析，代理人只在半开时间窗有效；撤回后重新提交必须生成新申请而非复用旧决定。

**题面全文。** 你是采购审批。提交时选用不晚于提交时刻的最新一份该部门策略。金额低于阈值就直接通过，否则按审批人顺序走。同意或拒绝只接受当前轮到的人；代理人只在开始时刻含、结束时刻不含的窗口里代替委托人，不改变走到第几步。拒绝后申请结束。全部步骤走完为已批准。已经结束的申请不再接受操作。事件编号重复时 trace 是 DUP。

**可机械判分的 20 点。** policy 版本；threshold 边界；AUTO；步骤顺序；错误审批人；代理起止；代理替代；代理不改步骤；批准完成；拒绝终止；终止后拒绝；重复提交；未知申请；重复 op；失败占 id；policy 隔离；read 字段；状态排序；时间边界；trace 等长。

**参考行为。** 提交时冻结 policy version；后续 policy 更新不改变已提交申请。代理只在审批事件时解析，且 from 自己的审批也仍然有效。

## CP-16 分层令牌桶与补偿

**业务锚点 / 失败代价 / 主能力。** API 网关按租户和全局两层限流；错误补偿会让突发流量穿透或把正常请求拒绝；主能力为推理。

**为什么更难。** 两层桶同时扣减，拒绝不能扣令牌；时间前进按整数补充但有上限，重放必须返回首次判定而不能再次扣减。

**题面全文。** 你是按租户和全局两层限流的网关。每个桶一开始是满的。处理事件前按经过的时间和速率补充，但不超过容量。请求要租户桶和全局桶都够，才同时扣；有一个不够就拒绝，两个桶都不变。补偿只能把成功请求的消耗还一次，还完不能超过容量。时间往回走时不倒扣。事件编号重复时 trace 是 DUP，并且必须沿用第一次的判定，不能再扣一次。

**可机械判分的 20 点。** 初始令牌；时间补充；上限截断；租户不足；全局不足；拒绝原子；成功双扣；cost 边界；同刻重放；REFUND；重复 REFUND；未知 request；时间倒退不回补；未知租户；重复 op；失败占 id；READ 当前值；全局隔离；租户隔离；trace 等长。

**参考行为。** 每个桶有 last 时间；事件 at 小于 last 时按 last 处理，不倒退。REQUEST 的首次结果写入 request 表，重复 op 直接返回 DUP，不重新计算。

## CP-17 缓存重建与失效代数

**业务锚点 / 失败代价 / 主能力。** 搜索服务从事实表重建缓存并处理迟到失效消息；错误代数会让旧内容覆盖新内容；主能力为推理。

**为什么更难。** 事实版本、缓存代数和重建快照三者独立；迟到失效只允许清理不新于它的版本，重建期间读请求必须看到旧快照或明确 MISS。

**题面全文。** 你是搜索缓存。事实有版本，只有更高版本才能覆盖。失效记下见过的最高失效版本，不删除事实；不高于该版本的缓存不能读。重建把当时还没被失效的事实抄进一个代号；重建开始之后的新事实不进入这一版。查看只看当前这版缓存，没有就是未命中。可以记下事实、失效和缓存，再按编号恢复；恢复不清除事件编号。事件编号重复时 trace 是 DUP。

**可机械判分的 20 点。** 高版本 UPSERT；低版本忽略；失效最高版本；失效不删事实；重建 generation；重建边界；旧缓存 MISS；新缓存命中；多 key 隔离；快照；恢复；恢复不清幂等；未知 generation；重复 op；失败占 id；读返回版本；事实排序；generation 单调；失效相等边界；trace 等长。

**参考行为。** generation 是完整不可变映射；REBUILD 事件在复制开始时取快照，复制后的同一事件不再吸收后续 UPSERT。READ 只看当前 generation。

## CP-18 时间价与退款基线

**业务锚点 / 失败代价 / 主能力。** 票务系统按购买时段、出发时段和退票时刻计算应收；错用当前价会造成大额退款差异；主能力为推理。

**为什么更难。** 价格版本在出票时冻结，退票基于冻结价但按退票窗口分段；改签生成新票并保留原票历史，恢复不能重复退款。

**题面全文。** 你是票务计价。票价按出发时刻落入的半开区间选取，购买时刻不能早于该区间的开始；同时有多段时取得开始更晚的，再按价目编号。出票时把价格冻住。改签只作用于还没退的当前票，按新的出发时刻重新计价，旧票留下，当前票换成新价格。退票只作用于当前票，而且只能成功一次：离出发超过 60 个时间单位退九成，超过 10 个退五成，否则不退，百分比向下取整。事件编号重复时 trace 是 DUP。

**可机械判分的 20 点。** 价段左闭右开；购买时价；最新价段；无价失败；改签重选价；原票状态；当前版本；早退窗口；中退窗口；临近出发；向下取整；退款一次；退款后改签拒绝；未知票；重复 op；失败占 id；read 状态；read 价格；read 退款；trace 等长。

**参考行为。** 票据保存版本链和 current 指针；REFUND 只写 current 版本并把票标为 REFUNDED。恢复不是本题接口，不能通过重新 BUY 模拟退款。

## 编码题共同审查结论

十题均有真实业务使用者和可描述失败损失；名称和数据可整体替换而不改变状态机；评分只比较返回 JSON 和 20 个行为断言。没有第三方版本猜测、无关日志、题面外操作或隐藏码表。正式实现前必须为每题写一个“删掉关键规则后的答案变化”测试，并用第二套独立模拟器核对参考行为。
