# 20260925 题库设计说明

## 目标

本版本继续采用单轮、禁工具调用，并把每题拆成 5 个等权行为组、总计 20 内容分。目标不是用超大输入制造超时，而是测量模型能否把一组相互作用的业务规则实现为可执行状态机。运行时仍按 `easy/medium/hard/extreme` 使用 4/8/12/16 分钟墙钟预算；半预算以内耗时系数为 1，之后线性降至 0.5。每次请求前加入独立随机盐，盐只用于防缓存，不改变答案。

## 编程题重新设计

当前实现版本为 `20260925-challenge-09`。v08 在官方 `deepseek-chat`（回包 `model=deepseek-flash`）上的 CP pass@1 是 0.625，高于 30%–50%；同一模型名不再换密钥重跑。v09 因此给每题增加一条写进题面的反常规规则，并让五个得分组都包含它。这仍是待实测目标，不是本地验证结论。

CP 题使用几十个事件以内的固定行为用例，失败可以保留其他组的过程分。每题严格是 5 组 × 4 个不同输入，禁止复制同一批样例充当 20 分；每题都包含正常路径与至少两类反事实或异常路径：重复、乱序、过期、回滚、冲突、依赖或边界。测试输入不把规模放大成主要障碍。

| 题号 | 场景 | 主要交互 | 档位 |
|---|---|---|---|
| CP-01 | 订单事件与库存 | 幂等键、行合并、状态机、补偿、快照；SHIPPED 的 RETURN 不改状态 | hard |
| CP-02 | 任务队列 | 租约、迟到回执、重试死亡；depends 只认 DONE，死亡或取消不级联 | hard |
| CP-03 | 权限判定 | 继承、deny、时间窗；`*` 通配不跨冒号，宽规则不能否决未命中的资源 | extreme |
| CP-04 | 配置发布 | 依赖序、回滚、环；具体环境覆盖 `"*"` 且双方不算冲突 | extreme |
| CP-05 | 账务结算 | 原子批次、费用、冲正；只有成功 REVERSED 的 tx_id 才释放 | extreme |
| CP-06 | 事件聚合 | 去重、半开窗口、AMEND；SEAL 不追溯，封窗前的事件仍然有效 | extreme |
| CP-07 | 资源调度 | 依赖、容量、取消边界；budgets 启动时扣减，完成不归还 | extreme |
| CP-08 | 规则引擎 | 嵌套谓词、写冲突、stop；changed 只比较本阶段开始，改回即失效 | extreme |

题面和可审计参考解分别在 `eval_bank_20260925/challenge_coding.py` 与 `challenge_refs.py`。参考实现只作为本地期望值来源，模型只能看到题面；评分器只接受一个 Python 围栏并要求 `POINTS n/20`。

## 评分原则

每个组由 4 个独立行为检查组成，一个检查中的多例必须全部通过才得 1 个点。参考解回放必须为 20/20；故意返回 `None` 的代码为 0/20，说明不存在格式奖励或“声明完成”奖励。错误响应、缺少围栏、工具链缺失仍按仓库既有合同处理，缺失不进入能力分母。

## 校准边界

本版本的档位是设计先验，不是模型能力结论。要得到目标的 50% 左右通过率，需使用实际的 DeepSeek 官方端点做至少一次独立批次，并记录真实模型标识、服务端 usage、耗时和错误率。若模型仍在 CP-05 至 CP-08 大面积满分，应优先增加规则交互或加入新的业务语义，而不是简单放大事件数量；若全部为零，应先检查题面歧义和参考实现。

## 已验证范围

工具链检查通过；8 道 CP 参考解均回放 `POINTS 20/20`；本地挑战与候选包回归测试通过。真实模型区分度、恶意代码隔离和活动题库接入不在本文件的本地验证范围内。
