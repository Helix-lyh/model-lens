# worldkit：条件参数化的推理题世界

worldkit 把一道推理题表示成一个「世界」：预设的条件模块相互作用，题面、参考答案和质量门禁都从同一份世界数据推出。题族：单骑手配送（`delivery`）、多段通勤（`trip`）、电梯调度（`elevator`）、十字路口信号（`signal`）、机场除冰（`deice`）、产线换型（`line`）、登机口指派（`gate`）、后厨两口灶（`kitchen`）、车队充电（`charge`）、急诊床位（`ward`），以及分段选择十五景（`or` 手术班组、`apron` 过站保障、`berth` 舱口作业、`agv` 拣货波次、`ticket` 客服时段、`gpu` 训练阶段、`galley` 出餐工序、`fresh` 生鲜补货、`canteen` 食堂时段、`plug` 车辆补能、`relief` 物资运送、`bed` 清床、`crowd` 入场安检、`maint` 检修工序、`drone` 配送架次）。段序固定，后一段等不等窗口取决于前一段的完成时刻。配送族已能逐字复现 20261023 的 NX-12 / NX-18。生成的题进探针题库，不进 `ACTIVE_ITEMS`，单独报告。每场景一道的清单在 `worlds/scenes_band/`（40/200）。出题作坊见 [worldkit-craft-20261019](worldkit-craft-20261019.md)。

代码在 `eval_bank_20260925/worldkit/`，测试在 `tests/test_worldkit_delivery.py`，生成与实测脚本在 `cursor_workspace/build_scripts/gen_worldkit_delivery.py`、`try_worldkit_live.py`。

## 世界

世界是纯 JSON 字典：

| 字段 | 含义 |
|---|---|
| `family` | 题族 id |
| `data` | 题族数据（道路、订单等） |
| `modules` | `{模块 id: 参数}`，每个模块是一条规则 |
| `objective` | 字典序目标，全部取最小 |
| `objective_conditions` | 可消融的目标层及其条件名（如 `late_n` → 先少迟到） |
| `questions` | 问题：`name`、`metric`、`points`，可选 `type`（exact / tolerance / plan）、`cf`、`accept` |
| `background` | 写进题面、但不参与删除测试的模块 |
| `gates` | 门禁阈值：`min_degree`（默认 3）、`min_boundary`（默认 0） |

题面只由「题族头部 + 各模块条款（按 stage）+ 目标 + 问题 + 答案行约定」拼出，不做字符串补丁。语义有歧义的地方做成模块参数（洪涝 `scope` 为送达前 / 到达前，停运 `check_at` 为开始上楼时 / 到达地面时），题面按参数写明。

## 求解与门禁

引擎（`core.solve`）枚举题族给出的全部方案，用题族的 `simulate` 逐个执行；不可行返回 `None`，不用大数哨兵。条件是模块、目标层和互斥规则的消融；删除测试和联合度数由此自动推出。

门禁（`gates.run_gates`）按代价从低到高：

1. 可解题：边界次数、反事实值与主值不同、主值唯一、删除测试、联合度数；
2. 无解题：冲突核——消融后变可解的条件构成 C，只放松其余条件后仍无解，且 |C| ≥ 2。取消订单、互斥、随时回站的消融会收紧可行集，放松时保留不动；
3. 独立复核器（`oracles/`，不得引用引擎或题族代码，有 AST 测试）在原世界、全部单删、全部双删上比较「最优方案主值集合」，原世界再逐题比较。

生成循环用 `fail_fast`：遇到第一个不通过就停，复核器只对前面全过的候选运行，但从不跳过。超预算记 `rejected:budget`。另有两项只报告不拒收：读法敏感度（换一种读法主值是否变化，供人工复核措辞）和「最优轨迹是否触发」——限制类规则常通过迫使最优方案绕开自己而承重，承重本身由删除测试保证。

## 答案与判分

最后一个 `ANSWER:` 行，每问一段，分号分隔。

- exact：整数等于参考值；
- tolerance：整数落在闭区间内，边界可写成相对参考值的偏移；
- plan：订单号用短横线连接，中途回站写 W；判分器用题族规则重放，可行且满足 accept（默认目标键等于最优）才得分。不允许随时回站时，写在强制回站处的 W 视为同一方案；
- 无解：参考值为无解的问只判是否明确写了「无解」，不判理由；整行只写一个「无解」视为每问都答无解；可解的问答无解不得分。

每题 20 分，按问分组计分，`score10 = 分数 / 2`。实测请求超时、没有答卷时记 0 分；网关 5xx 等请求失败不算超时，不记分。

## 生成

场景目录 `worlds/<场景>/` 放 `config.json`（参数范围与难度档）和 `presets/`（复现用世界）。难度档：

`deepseek-flash` 在旧困难档满分，所以整条梯度上移：新的简单等于旧困难，新的中等等于旧极难，再往上两档。

| 档 | 订单 / 楼宇 | 模块 | 目标 | 门禁 |
|---|---|---|---|---|
| 简单 | 5 / 3 | 旧困难：出餐、洪涝、互斥、反事实 | 迟到、时长、步行 | 度数 ≥ 3，边界 ≥ 1 |
| 中等 | 6 / 4 | 旧极难：去掉取消，随时回站、冷链，连续上限 2～3 | 同上 | 度数 ≥ 4 |
| 困难 | 7 / 4 | 同上，连续上限固定 2 | 同上 | 度数 ≥ 4；深度筛 `order`，预期百分制 20–40 |
| 极难 | 7 / 5 | 同上 | 同上 | 度数 ≥ 5；深度筛 `late`，预期百分制 0–20 |

困难和极难在原有门禁通过后再过三道深度筛，不增加订单、楼宇或模块种类。蝴蝶效应：只改一个参数，最优顺序或迟到集合改变，且另一个模块的触发情况也变。陷阱：一条规则允许的贪心路线（先送更紧的单、按未生效的突发来排、无视拥堵阈值）可行，但不是最优。困难要求存在一条贪心路线，顺序不同且迟到单数最多差 1。极难要求存在一条贪心路线，顺序不同且迟到单数至少差 2。同形干扰：冷链时限写在题面里、放在背景中，删掉不改变所问答案，收紧后会改变顺序或迟到集合。道路表写明一行就是两点直达分钟，不经其他地点。计分问上换读法会改主值的候选拒收。思考时长不是通过条件。

困难、极难各有一个无解档（`*-无解`），每道无解题配一道只改一个参数、门禁全过的近邻可解题；近邻题的边界要求放宽为 0，最多对 6 个可解变体跑门禁。

采样器先随机取参数，再把时限、出餐、封闭、停运和洪涝时刻锚定在「去掉这些规则后的最优轨迹」附近；纯随机取值时这些规则大多不承重（试采样中洪涝 69/73 不承重）。互斥生效时只有先发生的突发起作用，另一条记为背景，由反事实题考察。随机性只在生成时出现，冻结后题面固定。

生成时的门禁由 `gosolve/` 里的常驻进程计算：引擎和复核器各写一份，18 个核按消融变体并行。Python 仍负责采样、题面和判分；`tests/test_worldkit_gosolve.py` 用同一批世界对拍两边的门禁结论。

```bash
.venv/bin/python cursor_workspace/build_scripts/gen_worldkit_delivery.py --check               # 预设复现
.venv/bin/python cursor_workspace/build_scripts/gen_worldkit_delivery.py --tiers 简单 中等 --want 2
.venv/bin/python cursor_workspace/build_scripts/try_worldkit_live.py --n 2                     # 实测
```

## 已知局限

- 引擎、复核器与题面由同一人按同一理解编写，若对某条规则存在共同误读，三方对拍无法发现。缓解手段是读法敏感度报告、模块手算用例和人工审读题面。
- NX-12 的主值对停运判定读法敏感：题面已写明「开始上楼时」，仍建议人工确认措辞。
- 困难和极难有 7 个订单且允许随时回站，单次求解枚举 322560 条路线。门禁在 Go 里按变体并行。
