## 3. 方法核实

### 3.1 差分公式：原稿写窄了

原稿：

```
delta(x) = prompt_tokens(BASE + x) - prompt_tokens(BASE)
n_hat(x) = encode_k(x)          # 错
家族 = argmax exact_hits(delta == n_hat)
```

两份源头并不这样比。

**tokenizer-fingerprint**（与牛来鉴定一致）：BASE 与 BASE+probe 都当 user 消息发出去，再在**每个候选词表上对同一拼接做本地差分**。模板常数消掉，BPE 跨 BASE|probe 边界的 merge 也被同样处理。

**tokwhois**：用空 user 校准 `n_∅`，再和 `encode(s)`（无模板）比。METHOD.md 写明这是 **working hypothesis，不是恒等式**：BPE 不是加法，`Template(s)` 也不是 `Template(ε)+s`。缺 usage / 校准后 &lt;1 / 计数离谱则 abort，不猜。

因此：

- 隐藏系统提示「消常数」只在模板与内容无关时成立。按内容加工具头、按语言换模板、按长度加缓存标记，hits 会掉。这是已知、可接受的置信度下降，不是静默错家族的理由——前提是 **fail-closed**。
- 离线 `n_hat` 必须是 `encode(BASE+x) - encode(BASE)`，或走 tokwhois 空串校准并承认偏差。禁止 `encode(x)` 对 `delta(BASE+x)`。

### 3.2 New API 会改 usage

[New API #6212](https://github.com/QuantumNous/new-api/issues/6212) 等 issue：上游（尤其 streaming）不回 usage 时，网关用**本地 tokenizer 估算** `prompt_tokens`，可虚高数十个百分点。非流式透传往往还能对上。

这不是理论风险。F 模块若把估算值当上游词表，会把中转的计费词表认成模型家族。

必须：只走非流式；无 `usage.prompt_tokens` 或计数离谱 → F 标 `token_untrusted`，不出家族；禁止用网关自算值排名。

`max_tokens=1` 对计费差分足够。有的网关会忽略或抬高 `max_tokens`，只影响费用，不影响 `prompt_tokens`。

### 3.4 12 探针区分力

原稿 12 条（数字、π、汉字、日韩泰阿、emoji、黏词、混排、代码、零宽）方向对，但弱于源头电池：

- tokwhois 14 维显式打 **digit 分组、空白压缩、ChatML / `[gMASK]` / Llama BOS、稀有 script fallback**。
- tokenizer-fingerprint 用到 **95** 条才把 GLM-5 打到 95/95、非 GLM 掉到 ~46。
- 「避开冷门字」正确：国产模型普遍 byte-fallback，生僻字不分家。
- 泰文作为 GLM-4→5 扩展点：**成立**（白皮书实测 Thai 58 vs GLM-4.5 预测 69）。生僻汉字区分力弱，真正拉开的是泰/印地/孟加拉、ZWJ emoji、数字分组。
- 12 条 +「8/12 且领先 3」在 Qwen/DeepSeek/近亲上会经常落到中/低，或并列。这不是失败，但必须允许 `ambiguous`，禁止并列时仍输出单一家族。

### 3.5 验收数字的统计功效

24 题二项自算：阈值 ≥17/24（≈70%）时，若真一致率 p=0.50 假阳性约 3%；若真 p=0.70 功效只有 **56%**（漏报 44%）。17/24 的 Wald 95% CI 约 [0.53, 0.89]，包不住 15pp margin。单侧 70 vs 50、80% 功效约需 n≈37。

- 架构关键词即使同一模型也容易 20–30% 翻转，Hamming 会在「支持/存疑」间晃。
- 降智 15pp ≈ 3.6 / 24 题，两比例之差 SE 约 0.11，只有约 1.3σ。
- ICLR 论文要「每 prompt 约 10 个 completion × 20–25 prompt」才有中位 77% power。原稿用 1 次对错向量冒充该方法。

编码沙箱（subprocess + timeout + 无网）可跑，前提是 grader 先抽代码块再测；模型爱加解释，这是主路径，不是边缘。

家族 top-1 ≥70%（≥4 个公开家族）：用官方非流式 API、词表差分、L1+margin，**花钱不多即可验**（每端约 15–30 次 `max_tokens=1`）。这是唯一现在就站得住的验收项。

## 4. 对抗评审

60–80% 不是免死金牌。下面只列会系统性出错误结论或验收不可达的问题。

### 4.1 致命（必须改规则再写 I/D）

**F1. 中转重算 usage → 错家族**  
场景：New API streaming 或缺上游 usage，本地 tokenizer 填 `prompt_tokens`。  
伤害：家族栏对中转计费词表「高置信」认亲。  
60–80% 不可接受（这是工具坏了，不是准确率带宽）。  
最小修正：非流式 + fail-closed，见 design。

**F2. 24 题对错 Hamming 当「同一分布」**  
场景：官方 vs 官方，架构题换说法，编码题多写一行注释。  
伤害：判真误报「不支持」，直接打验收「误报 ≤30%」。  
不可接受。  
最小修正：删掉「Hamming=同一分布」。跨族换货只靠 F。知识/架构退出决策向量。无参考源 I=`skipped`。

**F3. 降智 15pp / n=24 功效不足**  
场景：参考源 18/24、待测 14/24。  
伤害：未降智报疑似，或弱模型漏检。  
目标带宽内可当粗筛，但必须改文案和阈值，不能写成「判定」。  
最小修正：升到约 25pp，或要求 pass0 与 stab 同时动；报告写「粗筛」。

**F4. 产品默认「只有 New API」却承诺判真**  
原稿 §11.8 假设用户只给中转三元组。没有参考源，I/D 按自己的规则必须 skip。  
伤害：用户问「是不是挂羊头」，只得到词表家族。  
可接受，但 CLI/README 必须把 `family` 当默认主路径，`audit` 无 reference 时明确 skip，禁止暗示三栏都能出。

**F5. 同家族换弱档（Flash↔Pro、Max↔Turbo）**  
F 必然过（一张词表）。知识题太简单则两边满分，I 变「支持」，D 未检出。  
这是用户最关心的「降智」，也是 60–80% 明确允许漏的。  
必须在报告固定写：「同家族弱档 / 8-bit 本工具经常看不出」。不要用协议探测假装能补。

### 4.2 重要（会错，但改完 F/I 规则后可忍）

| ID | 场景 | 伤害 | 最小修正 |

### 4.3 可接受限制（原稿已承认且合理）

- 不证明 INT4 / checkpoint hash / 法庭级
- 8-bit 漏检
- 不做多模态、不做 LLMmap 分类器、不上完整 MMD/RUT

## 5. 给执行的最小修正集

1. 仓库名 / 目录：`model-lens`，不要 `llm-audit`。  
2. F：同一拼接的本地差分；报告 L1 + exact_hits；margin 内 `ambiguous`；usage 不可信则不出家族。  
3. 只非流式。  
4. catalog：sha256 钉死；Phase 1 ≥5 家；不单列 MiMo。  
5. 探针 12–14，必须含 digit 分组 + 至少 2 条特殊 token（如 `[gMASK]`、`<|im_start|>`）。  
6. 默认 CLI：`family`。`audit` 无 reference → I/D = skipped。  
7. I：跨族换货只靠 F（非 untrusted）。同族不同 SKU → `同族未分型`，永不「支持」。架构和知识都不进决策向量。未登记声称型号 → skip。T/R 同网关 → `invalid`。  
8. D：`--quick` 不出；约 25pp **且** stab 同时破线；I=`支持` 与 D=`疑似` 互斥。  
9. 依赖：`httpx`、`pyyaml`、`tiktoken`、`tokenizers`。沙箱清空 API 环境变量。
