# 题库加难设计

日期：2026-09-26。读者用它决定下一版题库改什么、分怎么记、哪一项还不能拿去校准。

这是设计说明，不是模型能力结论。v09 还没有同口径实测。

## 要分开的三件事

现在的 24 题混在一次跑测里，但测的不是同一种能力。再加难之前先拆开，分数继续分栏，不合成 0–100。

| 栏 | 题号 | 模型在做什么 | 题面给多少 |
| --- | --- | --- | --- |
| 推理 | `R-E-01` … `R-X-02` | 自己把精确结果算出来 | 条件写全 |
| 编码与注意力 | `P-*` 与 `CP-01` … `CP-08` | 把写明的契约收成可执行程序 | 规则写全，评分器执行 |
| 工程能力 | 尚未建，建议编号 `E-*` | 用户只给一句需求时，补上生产环境该有的义务 | 只给任务和入口签名；义务和禁则在冻结的评分表里 |

无工具时，模型只有题面和它正在写的 token。注意力把题面里的句子取出来，生成时会沿着「这类系统通常怎么写」往下接。幻觉在这里的样子是：每个分支单独看都像对的，输出格式也对，两条规则碰到一起时多做了一次或少做了一次。

因此：

- 推理栏难在量词和多条约束同时成立。套一个著名公式，格式仍然正确。
- 编码栏难在同一次状态更新里，几条已经写明的规则互相改写。句子一旦被读到，多一个操作名并不会更难。
- 工程栏难在题面故意不写那些义务。模型要靠自己的工程习惯补上。这条和编码栏相反：编码栏里，没写的规则不算失分。

`challenge.py` 里的 `CR-01` … `CR-08` 没有接入当前 runner。它们和 `R-N-02`、`R-H-02`、`R-X-01`、`R-X-02` 同属搜索计数，不单开一栏。

## 编码栏怎样加难

复杂度来自真实工程，并且作用在同一次状态更新上。三类来源：

1. 业务历史和特例。同一条指令，旧记录和新记录含义不同。
2. 环境和版本。容量够但能力代际不够；废弃字段还要留给旧客户端，却不再参与新决策。
3. 产品义务。合规、隐私、留存互相挡住。例如抹除去掉标识，账务分录必须留下。

规则仍写在题面里。这一栏测的是注意力和实现，不是猜未写出的需求。不把输入规模放大成难点。`P-X-01` 这种竞赛规模不往这套加难里搬。

下一版编码题（建议仍叫 CP，契约版本顺延）按下面改。每题只加一个交点，并让它穿过一次恢复、回滚或跨版本。不新造一套操作名。

| 题 | 改什么 | 弱模型会做成什么样 |
| --- | --- | --- |
| CP-01 | 订单自带政策版本。旧单支付后仍可取消并退库存；新单支付后只能退货，状态保持已发货。快照保存版本戳 | 用新规则覆盖整条流，或恢复后丢掉版本 |
| CP-02 | 保留「过期先于回执」。前置 `DEAD` 或取消时，后继仍是 `PENDING`，不能领取，也不自动取消 | `until==now` 仍接受旧 token；前置一死就把后继取消 |
| CP-03 | 把单段通配写成资源路径：`doc:*` 匹配 `doc:1`，不匹配 `doc:1:2`。不适用的宽 deny 不能否决 | 星号当成前缀，整棵路径都拒绝 |
| CP-04 | 具体环境压过 `"*"`，与先后无关。回滚掉的具体变更不再压星号 | 两种环境写同一键就报冲突；回滚后星号仍被压住 |
| CP-05 | 抹除去掉可识别字段，分录和金额留下，冲正仍退金额加手续费。失败的冲正不释放交易号 | 把账删掉，或把标识原样返回；只退金额；失败也放号 |
| CP-06 | `SEAL` 写成关账：关账前已写入的事件仍然有效，只拒绝此后补进该窗口的事件 | 把整个窗口清空，或把之后的窗口一并关掉 |
| CP-07 | 预算在启动时扣、完成不归还。再加驱动代际：容量够但代际不够则跳过，且不扣预算 | 完成时把额度退回；任何空闲设备都分配 |
| CP-08 | `changed` 写成阶段提交：上一阶段的变化到下一阶段不再算变化；同一阶段改回原值后，后面的规则看不到 | 字段一旦变过，`post` 里继续触发 |

误导只放在模型已经会走错的那条路上。题面把正确顺序写清楚，旁边留一个看起来也合法的读法。例如「放宽约束价值一定上升」（`R-H-02` 已在用）、「拓扑排不掉的节点都是环成员」（`P-N-02`）、「先跑再报静态错误」（`P-X-02`）。

编码栏的主读数仍是每组是否通过。pass@1 继续要求 20/20。一个等号漏掉和整台机器写错都会变成不通过，所以校准和解题都要同时看组分数。`CP-02`、`CP-04`、`CP-05` 这种两次都错在同一组的，才当作难度证据。像 `CP-06` 那样跨轮翻转的，同一形状的用例要进到五个组，避免被一轮采样盖住。

## 工程能力这一维

真实使用里，用户往往只说「做个登录」。生产登录里还有锁定、会话、枚举、口令不可逆、审计不能漏口令。这些义务不能写进编码栏的题面，否则又变回「照着规格实现」。

单独做 `E` 题。第一题建议是账号口令登录。

夹具只固定入口：事件列表进，结果列表出。这是为了能跑评分器，不是业务提示。不评页面、组件拆分和命名。禁止用另一个模型打分。禁止工具时，测的是模型自己会不会补这些义务。若允许联网查「生产级登录清单」，测的是检索。

两本账，不合成一个分。

**义务账。** 做成一条可观察行为得 1 点。判性质，不判魔法数字。连续失败在 3 到 10 次之间锁定都算覆盖；只认「恰好 5 次」是在撞数。短程序少得分，不另罚。

**禁则账。** 程序真的做出坏事才记 1 笔。没有日志，不能因为「日志里没出现口令」扣分。同一事实只进一本账。明文口令若已经算没覆盖「不可逆校验」，就不再因为「状态里看得到原口令」扣第二次。多写了无害功能不扣。扣分只留给打破义务的行为。

登录题可以先冻结这 8 条义务：

| 义务 | 夹具如何认定 |
| --- | --- |
| 未知用户和错误口令的对外结果相同 | 两种输入的失败结果一致 |
| 口令不可逆 | 状态里没有提交的原口令，正确口令仍能通过 |
| 连续失败会锁定一段时间 | 阈值内失败之后，正确口令也被拒绝，过窗后恢复 |
| 登录更换会话标识 | 旧标识失效，新标识可用 |
| 登出使当前会话失效 | 同一标识再访问被拒绝 |
| 轨迹和错误文本不含口令 | 返回值里搜不到这次提交的口令 |
| 同一幂等键不产生第二套有效会话 | 重复请求只保留一个会话 |
| 锁定只作用于该账号 | 另一个账号仍可登录 |

禁则三条：对外区分了两类失败原因；轨迹或错误中出现口令；锁定被写成永久封禁且没有恢复路径。

报告写「义务 8 分里覆盖了几条、禁则触发了几条」。全覆盖且禁则为零可以叫严格通过。主读数是这两本账。这张表是抽过样的清单，不是登录的全部情形。表和题面一起版本化，改一条义务就升版本，不和旧分连成趋势。

弱模型的常见结果是：正向登录能通，口令原样留下，两种失败原因各写一句，会话用递增数字，失败次数只打印、不改变后续结果。强一些的模型会做哈希和统一报错，然后在锁定之后把会话固定住，或把口令写进审计。

工程栏的通过率目标等第一轮基线出来再定。不用它去把 CP 的 0.625 压进 30%–50%。

## 推理栏动哪里

推理题保持「条件写全、自己算完」。不加业务故事，不把搜索空间放大到超时。超时不进能力分母，放大规模不会留下难度证据。

只在弱模型会填错相邻答案的地方加对照：

- `R-N-02`：保留「没有首尾环形禁位」。对照值与错排数 `!n` 只差这一条。
- `R-H-02`：删掉的互斥不要刚好是唯一绑住最优解的那条，`delta` 可以为 0。
- `R-X-01`：`fixed` 和 `adaptive` 的差保持在 1 附近。v08 没稳定满分的就是这道题的量词。
- `R-X-02`：不再增加对称种类。它已经难在算不完。
